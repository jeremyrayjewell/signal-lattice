# Signal Lattice

![Signal Lattice preview](docs/media/preview.gif)

An audio-reactive, procedurally generated music video. Every scene is a
p5.js sketch driven by real analysis of a source track (onsets, RMS, band
energy, beat tracking) and assembled into an 8-segment, full-track video
using a deterministic, frame-addressable render pipeline.

Each scene was built as an independent visual study — many take a specific
artwork from E.C.H. (Eiichi Ishii)'s **dailycoding** series as a compositional
reference, but none reuse its source code. See [CREDITS.md](CREDITS.md) and
[docs/source-references.md](docs/source-references.md) for the full
attribution trail, and `docs/prototype-NN-study.md` for how each individual
scene was built.

## What's here

- **Scenes** (`src/prototype-NN/`): ~100 individually built p5.js sketches,
  each with a `states.js` (CALM/ACTIVE/EXTREME interpolation driven by audio
  features) and a `sketch.js` preview harness. Most have a matching
  `docs/prototype-NN-study.md` describing what was studied and how the scene
  was independently constructed.
- **Hybrids** (`src/hybrids-*/`): scenes that interweave two source scenes
  at the element level — each item (particle, shape, panel, etc.) from both
  sources is tagged and depth-sorted into one shared draw pass, rather than
  layering two whole frames.
- **Segments** (`src/segment-NN/`, `scripts/render-segment-NN.mjs`): the
  track is cut into 8 segments. Each segment script picks cut points at real
  audio transients, mixes `cut` and `introduce` (staggered fly-in) transitions,
  renders every frame offline through headless Chromium/Edge, verifies
  determinism, and muxes the result with the matching audio excerpt.
- **Shared infrastructure**: `src/timing.js` (seeded per-element randomness,
  staggered intro animation), `src/prototype-02/audio.js` (turns the
  analysis JSON into per-frame reactive controls), `scripts/analyze-audio.py`
  (full-track feature extraction + best-excerpt selection via librosa).

## Setup

Requires Node.js, Python 3 (with the packages in `requirements.txt`), and
FFmpeg/ffprobe on PATH. On Windows the renderer uses installed Microsoft Edge
by default; elsewhere run `npx playwright install chromium`, or point
`CHROME_PATH` at a browser executable.

```sh
npm install
pip install -r requirements.txt
```

This project doesn't ship any audio — bring your own track. Point the
analyzer at it (this also extracts and caches a 25-second excerpt used by
the individual scene studies):

```sh
python scripts/analyze-audio.py "/path/to/your/track.wav"
```

Segment renders re-extract their own excerpt directly from the source file,
so set an environment variable pointing at it:

```sh
# bash
export SIGNAL_LATTICE_SOURCE_AUDIO="/path/to/your/track.wav"
# PowerShell
$env:SIGNAL_LATTICE_SOURCE_AUDIO = "D:\path\to\your\track.wav"
```

## Running it

```sh
npm run dev                              # live preview at localhost:5173
node scripts/render-segment-01.mjs       # render one full segment
node scripts/render-prototype-05r.mjs    # render one scene's 25s study
```

Each render script prints its cut schedule, runs a determinism check
(out-of-order frame replay must hash identically to in-order), renders every
frame as a PNG, encodes with FFmpeg, and writes a contact sheet via the
matching `scripts/contact-*.py`. Output lands in `renders/`, which is not
tracked in git.
